# AI Content Factory — рабочие заметки · 2026-09

## 2026-09-10 · MVP план — часть 2

### Главный вывод

Главный bottleneck текущего MVP — **fashion creativity / fashion energy**. Технически система уже умеет собирать и генерировать контент, но shot concepts и карусели часто сходятся к безопасным, шаблонным решениям. Проблема креатива ощущается шире, чем один конкретный Creativity Gate.

### Failed gates: не молча выбрасывать

Rejected/failed gate не должен автоматически означать, что изображение потеряно навсегда.

Нужно вручную понять, **стоит ли конкретный fail доработки**. Если изображение очевидно не стоит спасать, возможно, это сигнал false positive на предыдущих стадиях: плохой кандидат прошёл слишком далеко по pipeline.

Для спорных случаев нужен понятный retry / correction flow, а не только `reject → drop`.

### Product Fidelity / Identity Gates

Текущий production test: из **90 изображений** потеряно:

- **6** из-за несоответствия товарам;
- **1** из-за несоответствия модели / identity.

Отсюда рабочие вопросы:

- нужен удобный UI для ручной обработки failed gates: быстро увидеть отклонённую картинку, причину и доступные действия;
- для сильного кадра, который не прошёл product fidelity, пробовать второй generation/correction attempt вместо молчаливого discard;
- одна из гипотез — ручной retry через browser generation на наиболее сильной image model;
- если точность передачи продукта недостаточна, добавить дополнительный корректировочный step;
- пока не ясно, запускать correction автоматически после fail или только после human approval;
- корректировочный reasoning step может идти через Claude или GPT: агент получает исходные refs + failed image + evaluator feedback и формирует более точную попытку.

Ключевой принцип: **сильную по креативу картинку имеет смысл пытаться чинить, если проблема локальная — product fidelity или identity.**

### Creativity Gate

На текущем тесте Creativity Gate убрал ещё примерно **8 изображений**.

Это пока самый спорный gate на hero-этапе: непонятно, насколько корректно он отличает действительно слабый fashion frame от просто необычного решения. При этом субъективно проблема с creative quality присутствует почти во всех генерациях, а не только в тех, которые gate отклонил.

Следовательно, Creativity Gate пока нельзя воспринимать как окончательную истину. Нужны human review, сравнение его решений с ручной оценкой и дальнейшая калибровка.

### Carousel Gates

Та же логика: failed carousel frame желательно **дорабатывать, а не молча удалять**, если сама идея/кадр перспективны.

Открытый вопрос: retry должен происходить автоматически по evaluator feedback или только после ручного подтверждения.

### Carousel Creativity — самый сложный bottleneck

Гипотезы, которые нужно проверять отдельно:

1. **Sol / более сильный reasoning model** может выдавать более креативные shot concepts и более сильную структуру карусели.
2. **Midjourney** может давать больше fashion energy на уровне изображения / визуального языка.
3. **Creative Reference Pool**: собрать базу референсов и использовать её как источник визуального словаря для pose, composition, camera, body language, environment interaction и энергии.
4. **Storytelling overfit**: возможно, в текущих prompts слишком сильный акцент на storytelling и объяснимое действие. Storytelling должен быть одним из возможных механизмов, а не обязательным условием каждой карусели и каждого кадра.

### Reference Library

Референсы нужно постепенно **собирать, классифицировать и держать перед глазами**, чтобы не искать их заново под каждую генерацию.

Полезно классифицировать как минимум по нескольким независимым осям:

- location / background / environment;
- posing / body language;
- composition / camera / framing;
- storytelling / narrative device;
- fashion energy / charisma;
- sellability / garment readability.

Позже reference library можно связать с embeddings / vector similarity для retrieval и контроля шаблонности.

### Если разделить creative problem на части

Не нужно требовать, чтобы каждый кадр сразу был идеален по всем измерениям. Проблему можно декомпозировать:

1. **Location / фон / background** — насколько среда сама создаёт сильный визуальный контекст.
2. **Posing / body language** — есть ли fashion-пластика, напряжение, характер.
3. **Storytelling** — есть ли история, если она действительно усиливает кадр; storytelling не обязателен.
4. **Sellability** — остаётся ли одежда желанной, понятной и коммерчески читаемой.

Для запуска Content Factory **не обязательно идеально решить все четыре оси одновременно**. Можно получить сильный контент за счёт 1–2 доминирующих механизмов при приемлемом уровне остальных.

Пример: **Closer Couture** показывает, что карусель может почти не опираться на сложный background — fashion energy может держаться прежде всего на позировании, модели, композиции и самих вещах.

### Generation cost / batching hypothesis

Сейчас разные shot concepts уходят отдельными image API requests, и каждый запрос повторно платит за большой input context / references.

Проверить вариант: **один prompt/context → три разных concepts / outputs** в одном generation request или другом batch-подходе, если provider это позволяет и качество не деградирует.

Цель — сократить повторные input tokens. Но это только гипотеза: экономия не оправдана, если diversity или управляемость разных concepts заметно падают.

### Daily Flow Analyzer

Нужен ежедневный analyzer всего Content Factory flow, который вечером, когда есть доступные лимиты, смотрит результаты production runs и предлагает улучшения.

Он должен анализировать не только финальные картинки, но и trace pipeline:

- где и почему теряются candidates;
- какие gates дают больше всего rejects;
- где возможны false positives;
- какие shot concepts повторяются;
- какие evaluator feedback повторяются;
- какие prompts / steps выглядят главным bottleneck;
- какие изменения стоит протестировать следующими.

Это должен быть **advisory learning loop**, а не агент, который автоматически переписывает production logic без human approval.

### Manual Review UX

Текущий процесс ручного контроля неудобен.

Нужен интерфейс, где по каждому кандидату сразу видны:

- изображение;
- текущий этап / gate;
- passed / failed;
- конкретная причина отклонения и score;
- evaluator feedback;
- исходный shot concept;
- быстрые действия: approve anyway / reject / retry / correction / открыть refs / сравнить с соседними candidates.

Цель: human-in-the-loop должен быть не аварийным ручным обходом pipeline, а нормальным рабочим интерфейсом MVP.

### Текущая философия MVP

Не пытаться до запуска довести до совершенства location, posing, storytelling, creativity evaluation, retry logic и automation одновременно.

Сначала добиться повторяемого production процесса, где человек может быстро:

**увидеть сильный кадр → понять конкретный defect → решить, чинить или выбросить → получить следующую попытку → собрать публикуемую карусель.**

Главный вопрос следующей итерации — не «как полностью автоматизировать Content Factory», а **как системно поднять fashion energy и при этом перестать безвозвратно терять хорошие почти-готовые candidates.**
