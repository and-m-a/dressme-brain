# ИИ-контент-завод

ИИ-контент-завод — более широкая система, которая превращает реальные товары каталога и решения [ИИ-стилиста](ии-стилист.md) в публикуемый контент.

ИИ-стилист — отдельный сложный механизм внутри этой системы: он отвечает за качество сочетаний. Контент-завод отвечает за то, какой editorial product сделать из найденных сочетаний: один образ, карусель, рубрику, генерацию изображения, пост и т.д.

## Текущая цель

Сейчас задача не в том, чтобы перебрать и сохранить все возможные комбинации товаров. Практический приоритет — стабильно получать 1–2 сильных публикуемых образа в день по приемлемой стоимости.

Текущий основной формат можно считать «образом дня»: stylist flow выбирает один сильный winner, после чего он идёт дальше в image generation и публикационный workflow.

## Стратегическое расширение: рубрика «С чем носить»

Текущая архитектура уже почти готова к другому формату контента.

Один run вокруг anchor не просто находит одного победителя. До финального выбора система успевает:

- сформировать несколько стилистических направлений;
- собрать shortlist;
- сравнить много сочетаний одним ranking-запросом;
- выделить несколько действительно сильных пар.

Поэтому с небольшой доработкой нового flow можно получить рубрику:

- «С чем носить этот топ»;
- «5 способов носить эту юбку»;
- «Одна вещь — несколько образов».

Вместо раннего схлопывания результата в одного winner новый flow может сохранить несколько сильных pairings для одного anchor и передать их дальше как единый editorial set.

## Возможная карусель

Пример будущего результата:

1. первый слайд — anchor и hook «С чем носить»;
2. второй — самый сильный / универсальный образ;
3. третий — другое настроение или другая формальность;
4. четвёртый — ещё одна сильная стилистическая версия;
5. пятый — summary, CTA или ссылки на товары.

То есть одна дорогая reasoning-сессия стилиста потенциально даёт не один disposable output, а несколько editorial assets.

## Почему это ценно

Один успешный stylist run со временем должен уметь давать:

- winner для текущего «образа дня»;
- несколько альтернатив для карусели «с чем носить»;
- объяснения, почему каждый образ работает;
- rejection knowledge — что с этим anchor лучше не сочетать;
- reusable knowledge для следующих публикаций.

Это повышает отдачу от одного и того же reasoning без необходимости строить exhaustive combinatorial search по всему каталогу.

## Будущая память / кэш стилиста

Если ИИ уже потратил деньги и время на разбор пары или на ranking нескольких вещей вокруг одного anchor, эту информацию не обязательно терять.

В будущем имеет смысл хранить и переиспользовать:

- approved pairings;
- rejected pairings и причины;
- сильные alternatives, которые проиграли winner только сравнительно;
- ranking вокруг anchor;
- copy / editorial angle для сильных комбинаций.

Это может дать:

- меньше повторных LLM/VLM расходов;
- быстрее новые контент-run'ы;
- накопление собственной compatibility-базы;
- готовую основу для «с чем носить» и других anchor-centric рубрик.

При этом cache — не вечная истина. Он должен быть привязан к версии данных: фото, Visual Passport, prompt/model и бизнес-контекст могут измениться и потребовать нового решения.

## Что делать сейчас, а что потом

Сейчас не надо превращать эту идею в большой storage/cache проект. Сначала нужно доказать качество основного pipeline и понять его реальные bottleneck'и по логам.

Текущий порядок:

1. стабилизировать anchor → directions → shortlist → ranking → image comparison;
2. добиться высокой доли реально сильных winner'ов;
3. затем добавить flow «с чем носить», который сохраняет несколько approved alternatives;
4. после появления повторного reasoning / заметных затрат — добавить явный reusable memory/cache layer.
